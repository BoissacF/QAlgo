We want to find the prime factors of N = 39, so 3 and 13.
Shor's algorithm is probabilistic, meaning we do not necessarily find these factors on the first measurement.

The algorithm must find the order r which,  for an integer a < 39, is the smallest k such that: a**k≡ 1 (mod 39)

The number of qBits needed for each register must be n such that 2**n>=N**2
Here, 11 qbits since 2**11 = 2048 is greater than 39**2 = 1521, whereas 2**10 = 1024 would not be enough
The circuit therefore has 22 qbits: the 11 top lines for the first register, the 11 bottom ones for the second

First possibility: "Winning the lottery". We randomly find a divisor of N, and the algorithm stops.

Otherwise:
In this simulation, a and r must satisfy the 2 hypotheses below:

- hyp 1 : r is even
- hyp 2 : a **(r/2) + 1 must not be divisible by 39

For this simulation, if one of these 2 hypotheses is not verified, we choose another value of a and restart.

A third hypothesis is tested but will not be verified here:

- hyp 3 : The order r must divide 2**n   where n is the number of qbits, here 11

Here a = 2 and the order is r = 12, since 2**12 = 4096 = 105x39 + 1
- hyp 1 : 12 is even, verified
- hyp 2 : 2**6 + 1 = 65 is not divisible by 39, verified
- hyp 3 : 2048/12 = 170.67 is not an integer, NOT verified, exactly as for N = 21

CAREFUL with the way the oracle is written. Here X goes up to 2047, and (2**X)%39 returns nothing as soon as X reaches 1024, because 2**1024 exceeds the largest floating point number of the machine. Repeated squaring is therefore required. That is what the oracle of this circuit does, written without any semicolon since the file format does not allow one in this text:
function f(X){
 let r=1
 let b=2
 let e=X
 while(e>0){
  if(e%2===1) r=(r*b)%39
  b=(b*b)%39
  e=Math.floor(e/2)
 }
 return r
}

Practical Steps:
- We must change the oracle function with the chosen value of a
- We perform a partial measurement of the second register (the last 11 bits)
- For the first register, we look at the possible measurements m in the "Probas" window

Since hypothesis 3 is not verified, we obtain many possible states.
We retain only those with the highest probabilities, here for the 1st register:
0, 171, 341, 512, 683, 853, 1024, 1195, 1365, 1536, 1707, 1877

We compute for these different possible measurements m: the value m/(2**n), 2 situations:
  1- If we obtain an integer → failure... we restart
2- If we obtain a fraction, we must find an approximation with a denominator smaller than 39 using the continued fractions method
Example: If we measure 171, the Euclidean algorithm gives:
2048 = 11 x 171 + 167
171 = 1 x 167 + 4
Thus,
171 / 2048 = 1 / (11 + 1 / (1 + 4/167)) which is close to 1 / (11 + 1) = 1 / 12

Since 12 is much smaller than 39, we verify that:
2**12≡ 1 (mod 39)
Thus, the order r = 12

If this was not the case, we would repeat a measurement. Here about one measurement in three gives the exact order, the same rate as for N = 21.

Finding the Factors
Once r = 12 is determined, we obtain two factors d1 and d2 of N such that:
d1 = PGCD(a**r/2 +1) and d2 = PGCD(a**r/2 -1)
2**6 = 64 which equals 25 modulo 39, so
d1 = PGCD(26, 39) = 13 and d2 = PGCD(24, 39) = 3
 Thus, here: 3 and 13

Testing Different Values of a
In this simulation, you can choose other values of a to test while verifying that hypotheses 1 and 2 are satisfied. Bases 7 and 11 also give order 12, bases 4 and 10 give order 6, and bases 5 and 8 give order 4, for which hypothesis 3 becomes true and the peaks become sharp.
